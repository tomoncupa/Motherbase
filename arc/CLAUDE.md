# ARC — Mind Canvas (CLAUDE.md)

Single-file mind-mapping app for Tom (solo fitness coach, PROTAGONIST brand). Everything lives in `arc/index.html` (~4,400 lines: CSS + HTML + one inline vanilla-JS script). No build step, no dependencies beyond Google Fonts CDN. Deployed by copying the file to `tomoncupa.github.io`. Built iteratively across ~15 versions in claude.ai; this file is the handoff brief.

**ARC is a sub-project of Motherbase.** It lives at `arc/` inside the Motherbase repo. This brief governs the `arc/` folder only; the repo-root `CLAUDE.md` (Daily Quest OS / LifeOS) governs everything outside it.

**This folder is canonical.** `arc/index.html` is the file to edit and the one under git. A byte-identical convenience copy may sit at `Downloads/arc_12.html`; if the two ever disagree, this one wins.

## Working rules

- **One file.** Never split into modules unless Tom asks. Keep it deployable by copy.
- After ANY edit: test in the browser, not with `node --check`. Node is not installed on this machine (checked 2026-08-20 and again 2026-09-14), so that step cannot be followed, and the root CLAUDE.md's method is better anyway because it runs the real thing: serve the repo with `py -3 -m http.server 8777 -d "<repo>"`, open `arc/index.html?cb=<something new>`, drive it with JavaScript and read the console, then run `_review.html?cb=<something new>` at the root and check every `arc:` line. The script contains the literal string `'<scr'+'ipt>'`, split on purpose: never "fix" it. A real closing script tag anywhere inside the inline script, even in a comment, ends the script early and silently truncates the app.
- Verify every `$('#id')` in JS has a matching `id=` in markup after edits (past regressions came from exactly this).
- Test in a real browser when possible (Tom's daily map is ~200 nodes). Commit per feature; Tom will revert via git if a pass breaks.
- Persist user data compatibly. **Maps live in the shared Motherbase store as rows, never as one blob** (`shared/records.js`, declared with `Rec.declare('arc', ['map','node','link'])`). One `map` row per map, keyed by map id, payload `{title, view, snaps, order}` and nothing else (no nodes, no links). One `node` row per node, keyed `mapId|nodeId`, payload the node object. One `link` row per link, keyed `mapId|linkId`, payload the link plus `ord`. In localStorage they appear as `mb.r.local|map||<mapId>`, `mb.r.local|node||<mapId>-<nodeId>` and `mb.r.local|link||<mapId>-<linkId>` (observed 2026-09-06). The current map is the setting `arc.current`. In memory nothing changed: `DB`, `M()`, `M().nodes` and `M().links` keep the old shape, and only loading and saving moved. `save()` is debounced 250ms and calls `dbToRows()`, which `Rec.set`s every map, node and link (an unchanged payload is skipped, so moving one node writes one row) and `Rec.del`s, as a tombstone, anything the workspace no longer has. Boot is two-phase: `load()` builds the workspace synchronously from the store's fast localStorage half via `rowsToDB()`, then `Rec.ready` runs the one-time migration, rebuilds from every row including big ones that live only in the store's IndexedDB half (a node with a pasted image), and redraws. **Suspected gap, read from code 2026-09-14 and not yet watched:** because the map row carries only those four fields, the per-map `edgeStyle`, `posGrad`, `rankColors` and `hideCousins` look like they reset on reload. Delete this sentence once that is checked or fixed. **History:** before 2026-08-27 ARC kept the whole workspace as one JSON blob, `{maps:[...],currentId,ts}`, in its own IndexedDB (`arc` db, `kv` store, key `db`, authoritative by `ts`) mirrored to localStorage `arc_v1`. `migrateBlob()` runs once, takes whichever of the two copies is newer, writes it out as rows and sets `arc.migrated`; it reads the old blob and deliberately leaves it where it is as a way back. Nothing writes `arc_v1` or `db` any more, and `load()` reads `arc_v1` only when the store is empty. On the test browser on 2026-09-06 `arc_v1` was absent and `kv.db` read back undefined. The `arc` IndexedDB is still used for exactly one thing: undo/redo history under `hist:<mapId>` (`{u,r}`, about 25MB per map, debounced 800ms), which stays on that device and is not in any backup. **Preferences** go through `pref(k, v)`, which reads and writes `setting` rows in the `arc.` namespace under the old name, so `arc_font` is the setting `arc.arc_font`; values stay strings because every call site expects that. These are in the store and travel with a backup: `arc_bg`, `arc_clip`, `arc_dashmove`, `arc_declutter`, `arc_expandfit`, `arc_fitresize`, `arc_font`, `arc_keys`, `arc_model`, `arc_palettes` (`{scheme:{bg,panel,line,ink,mut,acc,colors[6]}}`, per-scheme colour overrides stored only for schemes actually edited), `arc_snap`, `arc_space`, `arc_stream`, `arc_typecolors`. `migratePrefs()` copied any old raw-localStorage values across once, set `arc.prefsmoved`, and left the originals. **Two stay in raw localStorage on purpose:** `arc_key`, the API key, because a backup is a file that gets copied around and a secret does not belong in one; and `arc_theme` (`{scheme:name}`, written by `setScheme`), because theme choice belongs to the skin layer, which also keeps ARC's choice under `suite_skin.arc` through `Skins.for('arc')`. A new preference goes through `pref()`, never `localStorage` directly. Never break old maps.
- Test fixture: `arc/arc_fixture.md` (Tom's real exported map, ~870 nodes after import) — run layout/perf changes against it via `importMarkdown(await (await fetch('arc_fixture.md')).text())`.

## Architecture (the parts that must not regress)

**Canonical hierarchy layer `H`** — the single source of parentage. `H.parents/children/roots/isAncestor/walk` union the primary `node.parentId` with relation links (`link.rel==='child'` ⇒ a is parent of b; `'parent'` ⇒ b is parent of a). Consumers: Markdown export, presentation order, focus view, cycle guards. **No subsystem may infer hierarchy on its own.** Multi-parent is real: one node, several parents; Markdown intentionally duplicates it under each parent (path-based cycle guard only — never global visited-suppression). Positions/layouts follow the *primary* parent chain only (a DAG has no tree embedding); that asymmetry is accepted and documented.

**Edge geometry** — `edgeD(a,b,style)` for everything; `linkD` defers to `M().edgeStyle` unless a per-link `style` override exists (the only allowed exception). Anchors are 4-cardinal side-centers with **super Y-bias**: vertical anchors unless |dx| > 2.5·|dy| (same threshold flips ortho elbows vertical-first). Side exits extend along outward normals — lines never route behind their parent.

**Line pattern is semantic, never manual**: equal = solid & still · cousin = faded dash & still (hidden when `M().hideCousins`, always visible in focus) · everything else (tree edges + child/parent links) = dashed + drift animation (`arc_dashmove` is the only off-switch). Connection stroke = 50/50 `blendHex` of its endpoints; hierarchical links styled `.hier` to match tree edges.

**Color doctrine** — `nodeColor` chain: position-gradient (`posGrad`, hue around centroid) → rank colors (`rankColors` + `n.rank` F–S via `RANKC`) → `lineageBase()`: **no parent is primary for color — a node's inherited color is the equal N-way blend (`blendMany`) of every `H.parents()` entry's own resolved color**, then a descendant's manual `n.color`/`type` is blended 50/50 into that inherited blend (never emancipated). Depth for lightness falloff is the max depth across all parent branches + 1. Cycle guard is a per-branch copied `seen` Set (never a shared mutable one), so diamonds — two parents sharing a common ancestor — resolve correctly instead of short-circuiting. Lightness drops ~4/depth, saturation scales with node size — **except when the resolved base is greyscale (HSL saturation < 10), which stays greyscale across the full lightness range**. Without that exemption `shadeFor`s 38% saturation floor and 32-72 lightness clamp invent a hue out of nothing (#FFFFFF rendered as #d39c9c pink), which makes a white-on-black or black-on-white scheme impossible.

**Never-overlap** — `resolveOverlaps(fixedId)` (pair separation, pinned-vs-pinned skipped unless one is fixed) runs after: layouts, drag end, resize/scale end, branch expand, RPG expand, paste. Auto-adopt requires actual bounding-box overlap between the dragged node and a candidate (largest-overlap-area wins when several qualify) — proximity alone never adopts. `n.pinned` = user placed it; fan/auto-layout never moves pinned nodes.

## Feature inventory (all must keep working)

Canvas: left-drag = marquee multi-select (Shift adds, Ctrl+click = branch select), pan = Alt/right/middle-drag, wheel zoom 0.15–2.5, pinch, minimap ≥25 nodes, coach hints fade at 6 nodes, universe starfield (toggleable, reduced-motion safe). Nodes: Tab/Enter/Ctrl+Enter create (fan placement continues parent angle, vertical default, avg-font sizing, declutter), Space/click-selected/2×click/F2 edit, rich text (B/I/U, bullet/numbered/**checklist** `[]`→☑ click-toggleable outside edit, `[title]`→quote block), description line (Alt+Enter newlines), width grip + corner scale (no limits), align, roles T/S/B, ▾ minimize card, collapse `C`, states ◐✓🔒 `D`, F–S rank badges+frame, types, star-slides `S`, speaker notes `N`. RPG (`R`): 7 levels default, pips, active/passive, ✦ AI tier generation, node-clone Skill Card export 1080×1350. Edge styles: organic / straight / ortho, chosen per map. The **hand-drawn** curve (`edgeD(a,b,'hand')` — the organic curve resampled with a deterministic endpoint-seeded wobble) is deliberately NOT in that list: it belongs to the doodle scheme and is applied by `edgeStyleNow()`, which returns `'hand'` whenever `THEME_NAME==='doodle'` and the map's own setting otherwise. Every edge-drawing path (render, `linkD`, both PNG exports) must go through `edgeStyleNow()`; an explicit per-link style override still wins over it. Connections: X = parent→child pick w/ ghost line, 16px hit halos, right-click line = label(start/mid/end)/relation/style-override/reparent/detach/convert; right-click node = ancestry path, type, rank, ⊕ add parent, ✂ orphan, ⇌ transfer. Focus `O` = **temporary** top-down tree view (positions stashed/restored except user-moved). Arrange (menu/L): clean, tree, tidy — clean puts every depth on one row and keeps sideways positions, tree rebuilds top-down, tidy nudges; size-aware, spacing option, never resize nodes. Radial and bilateral were removed from the menu 2026-09-14 because Tom never used them: do not restore them. `layoutBranch` survives only for markdown import. Present `P` (star-filtering, notes HUD, stream mode w/ popup, per-slide edge pulses), Ctrl+K jump, markdown import, snapshots, undo (nodes+links), **schemes** (fonts/shape/texture only — every `body.theme-*` rule reads palette tokens, never a literal hex, so any scheme works in any colourway) with per-scheme editable palettes: labelled fields, hover-to-preview, return-to-default, saved separately per scheme (`applyScheme`/`setScheme`/`paletteFor`/`savePalette`/`clearPalette`), **configurable hotkeys** (`DEFKEYS/KEYS/KEYREV`, ⚙ grid, red = unassigned), instant tooltips, JSON/workspace backup, **chart-only transparent PNG export** (`exportChartPng(scope)`, scope = all / view / sel — no background, no UI chrome, faithful to the active scheme), read-only share export (`PRISTINE` + `ARC_SHARE` + `RO` guards), Claude API (keyless in claude.ai artifacts, `arc_key` self-hosted, model `claude-sonnet-4-6`).
