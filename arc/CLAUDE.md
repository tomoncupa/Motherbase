# ARC — Mind Canvas (CLAUDE.md)

Single-file mind-mapping app for Tom (solo fitness coach, PROTAGONIST brand). Everything lives in `arc/index.html` (~4,400 lines: CSS + HTML + one inline vanilla-JS script). No build step, no dependencies beyond Google Fonts CDN. Deployed by copying the file to `tomoncupa.github.io`. Built iteratively across ~15 versions in claude.ai; this file is the handoff brief.

**ARC is a sub-project of Motherbase.** It lives at `arc/` inside the Motherbase repo. This brief governs the `arc/` folder only; the repo-root `CLAUDE.md` (MOTHERBASE) governs everything outside it.

**This folder is canonical.** `arc/index.html` is the file to edit and the one under git. A byte-identical convenience copy may sit at `Downloads/arc_12.html`; if the two ever disagree, this one wins.

## Working rules

- **One file.** Never split into modules unless Tom asks. Keep it deployable by copy.
- After ANY edit: test in the browser, not with `node --check`. Node is not installed on this machine (checked 2026-08-20 and again 2026-09-14), so that step cannot be followed, and the root CLAUDE.md's method is better anyway because it runs the real thing: serve the repo with `py -3 -m http.server 8777 -d "<repo>"`, open `arc/index.html?cb=<something new>`, drive it with JavaScript and read the console, then run `_review.html?cb=<something new>` at the root and check every `arc:` line. The script contains the literal string `'<scr'+'ipt>'`, split on purpose: never "fix" it. A real closing script tag anywhere inside the inline script, even in a comment, ends the script early and silently truncates the app.
- Verify every `$('#id')` in JS has a matching `id=` in markup after edits (past regressions came from exactly this).
- Test in a real browser when possible (Tom's daily map is ~200 nodes). Commit per feature; Tom will revert via git if a pass breaks.
- Persist user data compatibly. **Maps live in the shared Motherbase store as rows, never as one blob** (`shared/records.js`, declared with `Rec.declare('arc', ['map','node','link'])`). One `map` row per map, keyed by map id, payload `{title, view, snaps, order}` and nothing else (no nodes, no links). One `node` row per node, keyed `mapId|nodeId`, payload the node object. One `link` row per link, keyed `mapId|linkId`, payload the link plus `ord`. In localStorage they appear as `mb.r.local|map||<mapId>`, `mb.r.local|node||<mapId>-<nodeId>` and `mb.r.local|link||<mapId>-<linkId>` (observed 2026-09-06). The current map is the setting `arc.current`. In memory nothing changed: `DB`, `M()`, `M().nodes` and `M().links` keep the old shape, and only loading and saving moved. `save()` is debounced 250ms and calls `dbToRows()`, which `Rec.set`s every map, node and link (an unchanged payload is skipped, so moving one node writes one row) and `Rec.del`s, as a tombstone, anything the workspace no longer has. Boot is two-phase: `load()` builds the workspace synchronously from the store's fast localStorage half via `rowsToDB()`, then `Rec.ready` runs the one-time migration, rebuilds from every row including big ones that live only in the store's IndexedDB half (a node with a pasted image), and redraws. **Suspected gap, read from code 2026-09-14 and not yet watched:** because the map row carries only those four fields, the per-map `edgeStyle`, `posGrad`, `rankColors` and `hideCousins` look like they reset on reload. Delete this sentence once that is checked or fixed. **History:** before 2026-08-27 ARC kept the whole workspace as one JSON blob, `{maps:[...],currentId,ts}`, in its own IndexedDB (`arc` db, `kv` store, key `db`, authoritative by `ts`) mirrored to localStorage `arc_v1`. `migrateBlob()` runs once, takes whichever of the two copies is newer, writes it out as rows and sets `arc.migrated`; it reads the old blob and deliberately leaves it where it is as a way back. Nothing writes `arc_v1` or `db` any more, and `load()` reads `arc_v1` only when the store is empty. On the test browser on 2026-09-06 `arc_v1` was absent and `kv.db` read back undefined. These are in the store and travel with a backup: `arc_bg`, `arc_clip`, `arc_dashmove`, `arc_declutter`, `arc_expandfit`, `arc_fitresize`, `arc_font`, `arc_keys`, `arc_model`, `arc_palettes` (`{scheme:{bg,panel,line,ink,mut,acc,colors[6]}}`, per-scheme colour overrides stored only for schemes actually edited), `arc_snap`, `arc_space`, `arc_stream`, `arc_typecolors`. `migratePrefs()` copied any old raw-localStorage values across once, set `arc.prefsmoved`, and left the originals. **Two stay in raw localStorage on purpose:** `arc_key`, the API key, because a backup is a file that gets copied around and a secret does not belong in one; and `arc_theme` (`{scheme:name}`, written by `setScheme`), because theme choice belongs to the skin layer, which also keeps ARC's choice under `suite_skin.arc` through `Skins.for('arc')`. A new preference goes through `pref()`, never `localStorage` directly. Never break old maps.

## Architecture (the parts that must not regress)

**Canonical hierarchy layer `H`** — the single source of parentage. `H.parents/children/roots/isAncestor/walk` union the primary `node.parentId` with relation links (`link.rel==='child'` ⇒ a is parent of b; `'parent'` ⇒ b is parent of a). Consumers: Markdown export, presentation order, focus view, cycle guards. **No subsystem may infer hierarchy on its own.** Multi-parent is real: one node, several parents; Markdown intentionally duplicates it under each parent (path-based cycle guard only — never global visited-suppression). Clean and Tree read tiers from `H` since 1.0.8 (`tierPlan`: a node sits one tier below its deepest parent, laid out under that parent); fan placement and Tidy still follow the *primary* parent chain.

**Edge geometry** — `edgeD(a,b,style)` for everything; `linkD` defers to `M().edgeStyle` unless a per-link `style` override exists (the only allowed exception). Anchors are 4-cardinal side-centers with **super Y-bias**: vertical anchors unless |dx| > 2.5·|dy| (same threshold flips ortho elbows vertical-first). Side exits extend along outward normals — lines never route behind their parent.

**Line pattern is semantic, never manual**: equal = solid & still · cousin = faded dash & still (hidden when `M().hideCousins`, always visible in focus) · everything else (tree edges + child/parent links) = dashed + drift animation (`arc_dashmove` is the only off-switch). Connection stroke = 50/50 `blendHex` of its endpoints; hierarchical links styled `.hier` to match tree edges.

**Top nodes are brand gold** (Tom, 2026-10-18): a node with no parent in `H` and something under it is drawn solid `#F0B323` with dark ink (`.node.top`, `isTopNode`), whatever colour it was given, and its branches inherit from it; Rainbow and Rank colours still win.

**Color doctrine** — `nodeColor` chain: position-gradient (`posGrad`, hue around centroid) → rank colors (`rankColors` + `n.rank` F–S via `RANKC`) → `lineageBase()`: **no parent is primary for color — a node's inherited color is the equal N-way blend (`blendMany`) of every `H.parents()` entry's own resolved color**, then a descendant's manual `n.color`/`type` is blended 50/50 into that inherited blend (never emancipated). Depth for lightness falloff is the max depth across all parent branches + 1. Cycle guard is a per-branch copied `seen` Set (never a shared mutable one), so diamonds — two parents sharing a common ancestor — resolve correctly instead of short-circuiting. Lightness drops ~4/depth, saturation scales with node size — **except when the resolved base is greyscale (HSL saturation < 10), which stays greyscale across the full lightness range**. Without that exemption `shadeFor`s 38% saturation floor and 32-72 lightness clamp invent a hue out of nothing (#FFFFFF rendered as #d39c9c pink), which makes a white-on-black or black-on-white scheme impossible.

**Never-overlap** — `resolveOverlaps(fixedId)` (pair separation, pinned-vs-pinned skipped unless one is fixed) runs after: layouts, drag end, resize/scale end, branch expand, RPG expand, paste. Auto-adopt requires actual bounding-box overlap between the dragged node and a candidate (largest-overlap-area wins when several qualify) — proximity alone never adopts. `n.pinned` = user placed it; fan/auto-layout never moves pinned nodes.

## Cards (2026-09-16)

Tom: "Have the flashcard mode be a separate tab within ARC ... for learning flash cardable portions of the skill knowledge", and "this is still desktop only". Answers the same day: the cards are coaching and nutrition facts, marketing and business ideas, and his own content lines; his own for now, Skool members later.

- **A card is not a skill, and the two schedules never meet.** A skill is something you can DO, tested on separate days; a card is a fact you either recall or you do not. Grading a card is not a hit on anything. A knowledge skill that wants cards points at them, and that is the whole link.
- **Rows.** `card`, key `mapId|cardId`, `{q, a, node, made}`; `node` is optional and is the node the fact came from, which is what lets a skill show its own cards and a session cover one branch. `crev`, key `mapId|cardId` and dated, `{g:[{t, g}]}`: every grade that day, 1 again to 4 easy. **Nothing derived is stored.** `cdState` replays the log, the way `skInfo` replays attempts, so two devices' reviews merge as rows and come out the same.
- **The schedule is FSRS since 1.0.6** (2026-09-30, Tom: "Yes"). `arc/ts-fsrs.js` is ts-fsrs 5.4.2's UMD build from jsdelivr, MIT, vendored unedited under a licence header, loaded with a plain `<script src>` and defining one global, `FSRS`. `cdF()` makes one scheduler: FSRS-6 default weights, `request_retention` 0.9, no fuzz (the replay must come out the same on every device), `maximum_interval` 3650, short-term on with EMPTY learning and relearning steps, so nothing is ever due in minutes and a second grade on one day goes through FSRS's same-day formula. `cdStateFSRS` replays `crev` rows in date order, each day's grades sorted by `t`, fed in at noon UTC of the row's date plus one second per grade (`cdAt`), because ts-fsrs counts gaps in UTC calendar days and Manila is UTC+8: a review at 7am would otherwise land on the day before. Due is `Day.shift(date, scheduled_days)`. `cdPreview` asks `repeat` at noon UTC today for the four button labels. A grade outside 1 to 4 reads as Good, as before. Nothing is stored: the same rows replay, so all past grades carried over and only the dates changed. `lapses` is now FSRS's count, an Again on a card already in review, so an Again on a brand-new card is no longer a lapse. Again also puts the card back three places along in the same round, which is session-only and never stored. New cards a day are capped (`arc_cards_new`, 20), and the rest wait.
- **The fallback is the old SM-2 style replay** (`cdStateSM2`, `cdPreviewSM2`, unchanged: `CD_EASE0` 2.5, floor 1.3, Again drops ease 0.2 and returns tomorrow, Hard drops 0.15 and times 1.2, Good 1 then 3 then gap times ease, Easy that times 1.3). It runs when `ts-fsrs.js` does not load, and for any one card whose FSRS replay throws, with a console warning either way. Import / export ends with the line saying which is running ("Schedule: FSRS-6, default weights, 90% recall." or "Schedule: SM-2. FSRS did not load.").
- **The tab** is `#cardsview`, a full screen over the canvas, opened by the toolbar's Cards button or `Q`. A scope picker studies every card or one skill's, the header counts due, new and all, and there are three modes: study, browse (a table with next due, times seen and lapses) and import/export. **The keyboard is the point:** space reveals then grades Good, 1 to 4 grade, Esc closes. While the tab is open its listener stops every key reaching the canvas, or Delete would delete the node behind it unseen.
- **Getting cards in:** right-click a node, Make a card from this node (its words become the question, its description or notes the answer, and the editor opens); Add card; or Import, which reads `front :: back` and tab-separated lines, so a spreadsheet or Anki export pastes straight in. Export copies every card as a spreadsheet, which is also how a deck would reach a Skool member. Copy a prompt for Claude asks for cards in the same `::` format and lists the fronts already held so they are not repeated.
